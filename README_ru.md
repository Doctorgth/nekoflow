**NekoFlow** — это специализированное десктопное приложение для ОС Windows, представляющее собой графическую оболочку (GUI) над клиентской частью сетевого решения **APTCP-SOCKS**. Программа обеспечивает маршрутизацию трафика и локальное проксирование через отказоустойчивый транспортный протокол APTCP (библиотека `aioptcp`), работающий поверх стандартного стека TCP.

Проект поставляется в формате **Portable**: архив содержит скомпилированный нативный лаунчер `NekoFlow.exe`, встроенный переносимый интерпретатор Python 3.12, необходимые системные бинарные файлы (ядро `sing-box` и драйвер `Wintun`) и графический интерфейс на базе PySide6.

## Архитектура сетевого транспорта (APTCP & aioptcp)

В основе работы клиента лежит протокол сессионного уровня **APTCP**, разработанный для обеспечения высокой отказоустойчивости сетевых соединений при нестабильном подключении к сети, переключении интерфейсов (например, с Wi-Fi на LTE) или изменении IP-адресов.

### Ключевые особенности транспорта:
1. **Логическая непрерывность канала (Resilience):** При разрыве физического линка TCP логическое соединение APTCP не разрывается, а переходит в состояние ожидания `DISCONNECTED_WAITING`. Передаваемые приложением данные буферизуются, а системные вызовы `send()` и `recv()` временно блокируются. После восстановления физического канала сессия возобновляется автоматически без потери пакетов и без разрыва пользовательских TCP-соединений.
2. **Защита от переполнения памяти (Backpressure / Flow Control):** Ограничение объема буфера отправки (по умолчанию до 5 МБ) предотвращает неконтролируемое выделение оперативной памяти при длительных обрывах связи.
3. **Безопасное возобновление сессий:** Повторное подключение защищено взаимной 3-этапной процедурой верификации (Challenge-Response Handshake) с использованием подписей HMAC-SHA256, полученных на базе общего секрета, выработанного в ходе первичного обмена Диффи-Хеллмана (2048-bit MODP Group). Это исключает возможность перехвата сессии (MitM) или атак повторного воспроизведения.
4. **Защищенное закрытие сессий:** Команда завершения сессии (`CLOSE`) подписывается уникальной HMAC-SHA256 сигнатурой текущей сессии, что защищает от сторонней инъекции пакетов закрытия соединения.

## Режимы работы клиента

Приложение поддерживает два основных сценария интеграции в операционную систему:

### 1. TUN Mode (Сетевой туннель)
В данном режиме трафик перехватывается на сетевом уровне с помощью виртуального адаптера `NekoFlow` (драйвер `Wintun`), управляемого маршрутизатором `sing-box` (ядро расположено в `bin/sing-box.exe`).
* **Раздельное туннелирование (Split Tunneling):** Маршрутизация настраивается так, чтобы в туннель направлялся трафик только тех приложений, исполняемые файлы которых добавлены в белый список (например, `chrome.exe`, `discord.exe`). Трафик остальных программ идет напрямую через физический сетевой адаптер, снижая нагрузку на удаленный сервер.
* **Глобальный туннель:** Весь трафик системы (за исключением локальных подсетей и служебных процессов) направляется в защищенный канал.

### 2. SOCKS Proxy (Локальный прокси-сервер)
Клиент запускает изолированный локальный SOCKS5-сервер на порту `3080`.
* Схема маршрутизации не затрагивает глобальную таблицу маршрутов Windows, что позволяет избежать конфликтов с другими виртуальными сетевыми интерфейсами.
* Трафик необходимых приложений направляется на локальный адрес `127.0.0.1:3080` вручную или с помощью внешних утилит перехвата (например, Proxifier или Postern).

## Авторизация и защита транспортного уровня

Система разделяет доступ на локальном уровне операционной системы и на уровне сетевого транспорта:

1. **Локальный доступ (Приложение/Proxifier → Локальный SOCKS-сервер)**
   * На уровне графического приложения NekoFlow локальный SOCKS-сервер на порту `3080` всегда функционирует **без авторизации** (анонимный доступ). Внешние программы-перехватчики (такие как Proxifier) должны подключаться к нему без указания пароля.
   * Если вам необходим строгий контроль доступа на локальном порту, вы можете использовать специализированные низкоуровневые системные утилиты или самостоятельно модифицировать клиентский код SOCKS-сервера в файле `client/socks_server.py`.

2. **Транспортная авторизация (Локальный клиент → Удаленный APTCP-сервер)**
   * Для авторизации на вашем удаленном сервере учетные данные прописываются непосредственно в графическом интерфейсе NekoFlow в меню **«Управление серверами»**.
   * Указанные в полях ввода имя пользователя и пароль должны строго совпадать с теми, которые были заданы при развертывании сервера (сохраненными в `users.jsonl` на стороне сервера).
   * Процедура транспортного хэндшейка выполняется клиентом автоматически в фоновом режиме. Сторонние утилиты (например, Proxifier) в этом процессе не участвуют.

3. **TLS-шифрование и управление сертификатами**
   * Если при настройке вашего сервера было активировано шифрование, вам потребуется передать публичный файл сертификата `.pem` на клиентский компьютер.
   * Рекомендуется создать папку с именем `tls` в корневом каталоге этого приложения (если она отсутствует) и поместить файл сертификата туда. После этого укажите относительный путь к сертификату в настройках выбранного сервера в интерфейсе программы.

## Важные рекомендации по стабильности и устранению неполадок

* **Проверка соединения перед подключением:** Перед тем как переключить главный тумблер в активное состояние, настоятельно рекомендуется открыть меню **«Управление серверами»**, выбрать текущий сервер и нажать кнопку **«Проверить»**. Программа выполнит тестовый изолированный хэндшейк с сервером и подтвердит корректность логина, пароля и доступность транспортного канала.
* **Инициализация TUN-интерфейса:** Из-за особенностей работы драйвера Wintun в ОС Windows, виртуальный адаптер `NekoFlow` иногда может создаваться или монтироваться не с первого раза. Если при попытке подключения в режиме TUN вы получаете ошибку инициализации интерфейса, рекомендуется **полностью перезапустить программу** от имени Администратора и попробовать установить соединение еще раз.

## Нативный лаунчер (NekoFlow.exe)

Запуск графической оболочки конечным пользователем производится через файл `NekoFlow.exe`. Он представляет собой C#-загрузчик, скомпилированный на основе `Launcher.cs`, который работает следующим образом:
1. Переводит рабочий каталог приложения в директорию расположения исполняемого файла.
2. С помощью WinAPI-функции `SetDllDirectory` указывает папку `python/` в качестве приоритетного каталога для поиска динамических библиотек.
3. Подгружает интерпретатор `python312.dll` с помощью системного вызова `LoadLibrary`.
4. Находит адрес точки входа `Py_Main` в DLL и вызывает ее, передавая в качестве аргументов путь к главному скрипту `main.py`.
5. Благодаря встроенному файлу манифеста `NekoFlow.manifest` процесс при старте гарантированно запрашивает UAC-права Администратора, необходимые для монтирования виртуального сетевого адаптера `Wintun` и перезаписи системной таблицы маршрутизации Windows.

## Настройка и развертывание сервера (Linux)

Для функционирования клиента необходимо развернуть серверный обработчик на удаленном виртуальном сервере (VPS) под управлением Linux. 

Исходный код и докер-окружение сервера находятся в репозитории: [APTCP-SOCKS](https://github.com/Doctorgth/APTCP-SOCKS)

### Быстрая установка сервера (Docker-контейнер):
Для автоматической сборки сервера и настройки TLS-шифрования выполните на сервере однострочную команду:
```bash
curl -O https://raw.githubusercontent.com/Doctorgth/APTCP-SOCKS/main/install.sh && sed -i 's/\r//' install.sh && chmod +x install.sh && ./install.sh
```
В ходе выполнения инсталлятор:

* Спросит желаемый порт подключения, имя пользователя и пароль.
* Сгенерирует самоподписанные TLS-сертификаты шифрования (`server/cert.pem`, `server/key.pem`).
* Выведет данные для подключения в консоль и напишет команду для поднятия сервиса в фоновом режиме.

* Обратите внимание что для корректной работы на сервере уже должен быть установлен Docker/Docker Compose (docker-compose).

## Настройка шифрования TLS

При необходимости протокол APTCP поддерживает стандартное шифрование транспортного уровня (TLS) для обеспечения конфиденциальности передаваемой информации и верификации подлинности удаленного узла.

1. **Подготовка сертификата:** Если шифрование активировано при настройке удаленного сервера, скопируйте файл публичного сертификата `cert.pem` с сервера на локальный компьютер. Рекомендуется сохранить его в папку `tls/` в корневой директории приложения.
2. **Подключение в клиенте:** В графическом интерфейсе NekoFlow откройте меню **«Управление серверами»**, выберите необходимый сервер, установите галочку **«Использовать TLS»**, нажмите кнопку выбора файла `...` и укажите путь к вашему файлу `.pem`.
3. **Проверка подлинности:** Использование TLS-сертификата гарантирует защиту канала от несанкционированного изменения передаваемых данных и подтверждает, что клиент установил соединение именно с вашим сервером.

## Тестирование и запуск в среде разработки

Разработчики могут запускать проект напрямую без использования встроенного лаунчера.

```bash
pip install -r requirements.txt
```

```bash
python main.py
```
