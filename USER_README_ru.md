## Что такое APTCP и зачем нужен бесшовный реконнект?

При использовании обычного интернет-подключения любой кратковременный сбой (просадка сигнала Wi-Fi, переключение на мобильную сеть LTE, секундная потеря пакетов у провайдера, кратковременный отход кабеля) приводит к тому, что все активные сетевые сессии мгновенно разрываются. Из-за этого вылетают загрузки файлов, обрываются SSH-сессии, зависают сетевые игры и рабочие приложения.

**Протокол APTCP решает эту проблему:**
* Если физическая связь пропадает, NekoFlow не закрывает соединение на стороне ваших приложений. Он переводит его в состояние ожидания.
* Как только связь восстанавливается (даже если у вас изменился IP-адрес), NekoFlow бесшовно возобновляет передачу данных с того места, где она прервалась.
* Для ваших программ этот процесс происходит абсолютно незаметно — никаких вылетов, ошибок соединений и прерванных сессий.

## Быстрый старт: Как запустить программу?

Для запуска графической оболочки используйте файл **`NekoFlow.exe`** в корне папки. 

* **Важно:** Для полноценной работы сетевого туннеля (TUN Mode) программу необходимо запускать **от имени Администратора**, так как операционной системе требуются соответствующие привилегии для настройки виртуального сетевого адаптера и изменения таблицы маршрутизации.

## Настройка режимов перехвата трафика

Программа предлагает два режима работы в зависимости от ваших задач:

### Режим A: Глобальный сетевой туннель (TUN Mode)
В этом режиме трафик перехватывается автоматически на уровне всей операционной системы через виртуальный сетевой адаптер `Wintun`.

1. Запустите `NekoFlow.exe` от имени Администратора.
2. Выберите режим **TUN Mode**.
3. (Опционально) Активируйте **Раздельное туннелирование**, если хотите, чтобы через защищенный канал работал трафик только определенных приложений (например, только `chrome.exe` или `discord.exe`). Списки приложений настраиваются по кнопке «Список приложений...».
4. Включите главный тумблер.

*Примечание: Если виртуальный адаптер Wintun не смог инициализироваться с первого раза попробуйте еще пару раз (особенность ОС Windows при освобождении ресурсов драйверов), если не удается то просто полностью перезапустите NekoFlow и попробуйте подключиться еще раз.*

### Режим B: Локальный прокси-сервер (SOCKS Proxy) + Proxifier
В этом режиме NekoFlow не вносит изменений в системную сетевую карту, а поднимает локальный анонимный прокси-сервер на порту **`3080`**.

Чтобы направить трафик нужных вам программ через этот порт, используйте утилиту **Proxifier**:
1. Запустите NekoFlow в режиме **SOCKS Proxy** и активируйте подключение.
2. Откройте **Proxifier** -> **Profile** -> **Proxy Servers...**
3. Нажмите **Add** и укажите параметры локального прокси-сервера:
   * **Address:** `127.0.0.1`
   * **Port:** `3080`
   * **Protocol:** `SOCKS Version 5`
   * **Authentication (Авторизация):** Снимите галочку (анонимный доступ, логин и пароль вводить не нужно).
4. Нажмите **OK** и настройте правила распределения трафика (Proxification Rules) для необходимых приложений.

## Настройка шифрования TLS

Для защиты передаваемых данных от несанкционированного изменения в канале связи, протокол APTCP поддерживает шифрование TLS:

1. Если при настройке вашего сервера было включено TLS-шифрование, возьмите файл публичного сертификата **`cert.pem`** с вашего сервера.
2. Создайте в корневой папке NekoFlow папку с именем **`tls`** (если ее там еще нет) и скопируйте файл сертификата в нее.
3. Откройте в NekoFlow меню **«Управление серверами»**, выберите ваш сервер, поставьте галочку **«Использовать TLS»** и через кнопку выбора файла `...` укажите путь к вашему файлу `.pem`.
4. Нажмите кнопку **«Проверить»**, чтобы убедиться, что хэндшейк шифрования проходит корректно и связь установлена.

## Развертывание собственного сервера

Клиент работает только при наличии вашего собственного сервера. Сервер разворачивается в среде Linux через Docker.

* **Репозиторий сервера:** [APTCP-SOCKS](https://github.com/Doctorgth/APTCP-SOCKS)
* **Минимальные требования:** Установленные на сервере утилиты `docker` и `docker-compose`.

### Команда быстрой установки сервера:
Выполните эту команду в терминале вашего Linux-сервера для автоматической сборки контейнера:
```bash
curl -O https://raw.githubusercontent.com/Doctorgth/APTCP-SOCKS/main/install.sh && sed -i 's/\r//' install.sh && chmod +x install.sh && ./install.sh
```
В процессе работы скрипт предложит ввести порт, логин, пароль, сгенерирует ключи шифрования и запустит серверный контейнер в фоне.
